# ADR-030: Caster ships its own audio devices, "Caster Audio" and "Caster Mic", installed from the "Plays on" choice

- **Status:** accepted (2026-11-14). The follow-up [ADR-029](ADR-029-sound-follows-syphon-and-a-chosen-output.md) names. Renames and ports the HAL plug-in of [ADR-008](ADR-008-virtual-audio-devices.md) to the native receiver; ADR-008's Electron install row is not ported. UI designed and approved by the product owner on 2026-11-14 (frames 08–09 of `designs/desktop-signal-deck.figcraft`).

## Context

ADR-029 gave each track a **Plays on: Speaker | Caster** choice. "Caster" meant the first installed of `Caster Audio`, then the Electron receiver's `Zero-Friction Game Audio` (and the same for the mic). Nothing installed `Caster Audio`: the native receiver could only borrow the devices of an obsolete app, and on a Mac without them the choice was disabled. A user setting up OBS with Syphon (which carries no sound) had no way to get the sound into OBS from Caster itself.

## Decision

1. **A new plug-in, `CasterAudio.driver`**, with two loopback devices, **"Caster Audio"** (the game's sound) and **"Caster Mic"** (the phone's mic). The same libASPL code as ADR-008 (pinned commit, ring buffer, 48 kHz stereo float32), with new identities so it never collides with the plug-in it replaces: bundle id `app.caster.audio`, factory UUID `D77F71F7-9EFE-47B2-B1FC-7279F5967700`, and **fixed device UIDs** `app.caster.audio.CasterAudio` / `app.caster.audio.CasterMic` (ADR-008 left them to libASPL's default; OBS remembers a device by its UID). Two devices, never one shared: the tracks never mix (ADR-003).
2. **Installing it removes `ZeroFrictionAudio.driver`.** Two pairs of near-identical devices would only confuse an OBS device list. The cost: an OBS scene that captured "Zero-Friction Game Audio" must be pointed at "Caster Audio" once. The Electron receiver, the only other user of those devices, is obsolete (roadmap, Feature 2026-11f).
3. **No fallback to the old devices.** "Caster" means only "Caster Audio" / "Caster Mic"; the native receiver no longer knows the Zero-Friction names (product owner, 2026-11-14, replacing ADR-029 decision 4's fallback). While a track's Caster device is missing, its Caster half offers the install. A saved Caster choice without the device shows and plays Speaker; the engine keeps looking for the Caster device each time the output opens, so after the install (whose `coreaudiod` restart reopens every output) it plays there without another click.
4. **Installed from the choice itself, no Install button** (the approved design):
   - Missing device: the Caster half stays clickable and shows a round ⓘ. Hover or keyboard focus shows "Caster Audio isn't installed on this Mac yet. Click it to install — macOS asks for your password once." It is the button's `aria-describedby`, so a screen reader reads it too.
   - Click: Speaker stays selected and keeps playing; the Caster half is outlined with "Installing…" and a spinner; "macOS is asking for your password." under it.
   - **installed**: the clicked track moves to Caster; ⓘ is gone on both tracks (one plug-in, two devices).
   - **declined** (the password dialog cancelled): back to rest, no message — the user chose not to.
   - **failed**: Speaker, with "Couldn't install Caster Audio. Try again." The detail goes to the `virtual-audio` log.
5. **How it installs** (`virtual_audio.rs`): the app bundle carries the plug-in in `Contents/Resources/CasterAudio.driver` (built universal and signed ad hoc like the app by `apps/desktop-native/caster-audio/build.sh`; the built bundle is committed, as ADR-008's was, so building the app needs no cmake or network). `osascript` runs `do shell script … with administrator privileges`: macOS's own password dialog, and the receiver never sees the password. The receiver first copies the plug-in, as the user, to a temporary folder: a root shell cannot read an app kept in a privacy-protected folder (Documents, Downloads, Desktop), and `cp` failed "Operation not permitted" when it tried (found live). As root: copy it in beside the installed one as `CasterAudio.driver.new`, and only once that worked remove the old plug-ins and move it into place, then restart `coreaudiod` (launchd brings it back). The first version removed first; its failed copy left the Mac without a plug-in. The outcome is read from osascript (AppleScript error −128 is a cancel) and from disk, then **installed** only once both devices enumerate (within 10 s). Paths are quoted for the shell and for AppleScript, so an app in a folder with spaces or quotes installs the same.
6. **"Caster" is looked up when the output opens, not stored as a name** (`audio::Destination::Caster`). Found live on 2026-11-14 before decision 3: the audio track played on the stand-in "Zero-Friction Game Audio"; the install removed it, and the reopen kept asking for that name — silent until the user switched by hand.
7. **A dead output reopens itself.** Restarting `coreaudiod` stops every running cpal stream without an error callback; before this ADR the track then stayed silent until the next device change or app restart. Each engine now stamps its device callback; when audio keeps arriving but the callback has not run for a second, the stream is dropped and reopened, and a failed reopen is retried a second later (the first three attempts logged, then every tenth). A reopen never falls back to the speakers when the chosen Caster device is missing for a moment: a track on Caster must not leak into the room while the device comes back.
8. **The plug-in's input never lags its output by more than 170 ms.** ADR-008's ring let the input side read from wherever it last stopped: a capture that started after the receiver had played for a while first played back about 1 s of **old** audio (measured: 1 013 ms on Caster Audio, 739 ms on Caster Mic, both tracks then on Speaker), and then trailed the output by a random part of the ring (up to 0.68 s). When the input trails by more than 8 192 frames, it now jumps to the newest audio (that one read is silent). A first fix kept two IO buffers and still let 8 ms of old audio through. The Electron app's copy (`apps/desktop/resources/zfaudio`) keeps the old ring.

| Option | Verdict |
|---|---|
| Keep the ADR-008 plug-in and its "Zero-Friction" names | Rejected by the product owner: the product is called Caster (ADR-027), and the UI and OBS would keep showing an old name |
| Count the old Zero-Friction devices as installed (no ⓘ) | Rejected by the product owner: those Macs would never move to Caster's devices |
| Keep the Zero-Friction names as a fallback for a saved Caster choice | Rejected by the product owner (2026-11-14): Caster's code names only Caster's devices |
| A shared driver source for the Electron and native apps (`drivers/`) | Rejected by the product owner: only the native receiver ships it. `apps/desktop/resources/zfaudio` stays untouched with the obsolete app |
| A separate Install button or row (ADR-008's) | Rejected in the design: the user's question is "where does it play"; the install belongs to that answer |
| Install without restarting `coreaudiod` | Not possible: Core Audio loads HAL plug-ins only at startup |
| A privileged helper (SMJobBless / SMAppService) | Rejected: needs a Developer ID the project does not have; one password, once, is the same friction as ADR-008 |

## Consequences

- One password, once per Mac. Installing pauses every sound on the Mac for about a second (the `coreaudiod` restart); the cast's sound comes back by itself (decision 6).
- An existing OBS scene that captured the Zero-Friction devices must be re-pointed at Caster Audio / Caster Mic.
- No in-app uninstall. The developer path: `sudo apps/desktop-native/caster-audio/install.sh --remove`.
- The plug-in runs inside `coreaudiod`; a crash there takes all system audio down (ADR-008's cost, unchanged code).
- Changing `src/Driver.cpp` means rebuilding with `build.sh` and committing the bundle.
- The receiver offers the install only while a device is missing; it does not compare the installed plug-in's version with its own. A future plug-in change needs that check (or a reinstall offer) to reach Macs that already have it.

## Verified (2026-11-14, Lenovo TB321FU → MacBook Pro M1 Pro, release bundle from `tauri build`, devices read back with ffmpeg from their inputs)

- `cargo test --lib`: 103 passed, 2 ignored. New: `a_cancelled_password_dialog_is_declined_not_failed`, `the_install_copies_first_then_replaces_both_plugins_and_restarts_coreaudiod`, `an_odd_app_path_reaches_the_shell_as_one_word`, `staging_copies_the_whole_bundle_out`, `only_a_bundle_with_an_info_plist_counts_as_bundled`, `an_output_that_stops_calling_back_is_reopened_once_a_second`; `each_track_gets_its_own_caster_device` now checks that the Zero-Friction devices do not stand in; the logger test covers the `virtual-audio` scope.
- The bundle: `codesign --verify --deep --strict` "valid on disk"; `Contents/Resources/CasterAudio.driver` is universal (x86_64 arm64) and ad hoc signed.
- **Install from scratch** (no Caster plug-in on the Mac, app run from `~/Documents`, cast live): the product owner saw ⓘ and the tooltip on both tracks, clicked Caster Audio, saw "Installing…", typed the password. Log: `installing CasterAudio.driver` 06:34:23.0 → both outputs `stopped calling back — reopening` 06:34:27.0 → speaker output reopened 06:34:28.2 → `installed — Caster Audio and Caster Mic appeared after 2398 ms` 06:34:28.5 → `Game plays on: Caster`, `audio output: Caster Audio` 06:34:28.9. The mic, saved on Caster with no device, found Caster Mic by itself at 06:34:29.3 (third reopen, no click). The installed plug-in is byte-identical to the build. An earlier run (the first build) replaced the ADR-008 plug-in the same way: `ZeroFrictionAudio.driver` gone, only Caster Audio and Caster Mic listed.
- **Both devices carry the cast** (10 s each, both tracks on Caster, sound on): Caster Audio mean −15.6 dB / peak −5.8 dB; Caster Mic mean −43.3 dB / peak −14.3 dB.
- **The tracks never mix:** Mic off, audio on Caster Audio → Caster Audio −15.6 dB, **Caster Mic −91.0 dB** (digital silence). Mic on, audio off → **Caster Audio −91.0 dB**, Caster Mic −26.4 dB.
- **Sound comes back after a `coreaudiod` restart mid-cast** (the plug-in reinstalled, both tracks on Caster): restart at ≈06:25:47; both engines logged `stopped calling back` at 06:25:48.7 and `reopened after 1 attempt(s)` at 06:25:50.2. Afterwards Caster Audio −15.6 dB / −5.7 dB peak, Caster Mic −30.7 dB / −4.5 dB peak.
- **No old audio on a new capture** (decision 8; audio moved to Speaker after playing on Caster Audio): ADR-008's ring 1 013 ms of old audio; the first fix 8 ms (384 samples); the final plug-in **0 non-zero samples** in 6 s.

**Not verified:** OBS itself capturing Caster Audio / Caster Mic next to the Syphon picture; the "failed" path in the UI (no way to make the copy fail on purpose short of breaking the Mac); keyboard focus and VoiceOver reading the tooltip (only hover was seen); an Intel Mac.
